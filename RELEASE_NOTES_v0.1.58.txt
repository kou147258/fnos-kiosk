v0.1.58 (2026-09-21)

修复：浏览器设置页「16:9 viewport」「自适应显示器」按钮保存被拒

v0.1.45 引入「窗口尺寸」段（16:9 / 自适应显示器 / 严格匹配显示器 / 1280×800 / 1920×1080 / 自定义）
6 个预设按钮，但 `dash_config.py` 里 `_sanitize(browser_window)` validator 只接受两种值：
- `"match_fb"` 字面量（或 `fb` / `auto` 别名）
- `[W, H]` 数组

UI 上点「16:9 viewport」按钮（settings.js:344-345）会写入 `cfg.browser_window = "match_dashboard"`，
「自适应显示器 ×1.25」按钮（settings.js:342-343）会写 `"match_fb_wide"`，保存时被 validator 一刀切
当非法值拒掉，红条提示「browser_window 必须是 [W, H] 数组或 'match_fb'」。

v0.1.45-v0.1.57 这两个按钮等于摆设——能点但保存不进去。这次把 validator 扩到接受所有合法字面量
并归一化：

| 写入值 | 归一化为 |
|---|---|
| "match_fb" / "fb" / "auto" | "match_fb" |
| "match_dashboard" / "16:9" / "wide16" | "match_dashboard" |
| "match_fb_wide" / "wide" / "1.25x" | "match_fb_wide" |
| "url_desktop" (v0.1.57 新加) | "match_dashboard"（前端实际写 match_dashboard）|
| [W, H] 数组 | clip 到合法范围（320-7680 / 240-4320）|

如果用户写入非以上任何一种合法字面量，错误信息会列允许的清单，便于自查。

变更文件：
- app/bin/dash_config.py   (_sanitize browser_window 接受 match_dashboard / match_fb_wide 系列；
                           错误信息列允许值；版本号 0.1.57 → 0.1.58)
- manifest                 (version=0.1.58)
- com.fnos.kiosk.fpk       (重打包)
