v0.1.59 (2026-09-21)

修复：v0.1.57 的 1920×1080 viewport 在你 dashboard 上触发 4 列布局

v0.1.57 把 URL viewport 锁到 1920×1080 是为了「绝对超过任何 3 列断点」——但你这个 dashboard
刚好相反：在 1920 宽度上 CSS 进 4 列布局（只看到 4 张卡），在 1280 宽度上才是 3 列（6 张卡）。
所以更大的 viewport 反而更糟。

v0.1.59 修正：

1. URL viewport 默认值改回 **1280×720**（精确等于桌面 reference 截图的浏览器窗口大小），
   dashboard 在此 viewport 进 3 列布局，6 张卡完整可见。

2. 新增 `cfg.url_viewport_size = [W, H]` 设置 + 校验，让用户在「浏览器」tab 可以选其他基准尺寸：
   - 1280×720（推荐，与桌面 reference 同尺寸，覆盖大多数 dashboard）
   - 1366×768
   - 1440×900
   - 1920×1080（如果某个 dashboard 设计稿就是这个尺寸）
   - 自定义（W × H）
   这样如果换别的 dashboard、4 列断点恰好不是 1280 而是 1366 / 1440 / 1920，用户可以从
   设置页调整而不必等我改代码。

实现：
- fb_render.py 冷启动 + 热加载两处 URL viewport 路径都接受 `cfg.url_viewport_size`，
  缺省用 1280×720。
- dash_config._sanitize 接受 list [W, H]，clip 到合法范围 (320-7680 / 240-4320)。

后续版本会把这个选项加到 settings.js 浏览器 tab UI（预设按钮 + 自定义输入）。
本次 v0.1.59 先把后端支持加好，UI 入口在 v0.1.60 配合。
